# Автоматическая серверная публикация Master на Fornex

## Pipeline

1. `Build server release` выполняет тесты, TypeScript-проверку и сборку интерфейса. Затем устанавливает Composer-зависимости без dev-пакетов и создаёт ZIP + SHA-256.
2. Отдельный интеграционный тест устанавливает архив на одноразовую MySQL 8.0, проверяет авторизацию установщика, миграции, обновление, сохранность APP_KEY/storage, отказ при повреждении архива и откат.
3. Только успешный release из `main` запускает `Deploy Master application`. Workflow скачивает именно проверенный artifact и шифрует его AES-256-GCM перед загрузкой по FTPS.
4. Короткоживущий установщик принимает только фиксированные операции install/rollback, проверяет токен, срок 15 минут, SHA-256 и GCM-тег. Ключ расшифровки и пароль БД передаются в HTTPS POST, не записываются в публичные файлы и не выводятся в лог Actions.
5. Архив распаковывается в приватный каталог. Перед миграциями создаётся SQL-копия БД. При первой установке непустая неизвестная база отклоняется. Проверяется `/login`, затем переключается release и публикуются только launcher, статика и правила маршрутизации.
6. Workflow проверяет реальные `/login`, `/register`, `/up` и недоступность приватных файлов. При неудаче переключает приложение обратно. Временный установщик и зашифрованная загрузка удаляются всегда.

## Серверные пути

- Web root: `/home/n66843/public_html/edu.china.kg` — launcher `index.php`, `.htaccess`, `build/`, favicon/robots.
- Приложение: `/home/n66843/master-app/releases/{sha-run-attempt}`.
- Активный release: `/home/n66843/master-app/current`.
- Секреты и постоянные данные: `/home/n66843/master-app/shared/.env` и `shared/storage`.
- Резервные копии: `/home/n66843/master-app/backups/{release}/database.sql`, исходные index/.htaccess и предыдущий `.env`.
- Состояние deploy и ошибки: приватный `deployments/`.

`.env` создаётся с правами 0600, APP_DEBUG=false, APP_ENV=production, secure cookies. APP_KEY генерируется при первой установке и сохраняется при обновлениях. Реальные тестовые учётные записи в production не создаются.

## PHP

Проверено PHP 8.3.33 (LiteSpeed). Для домена нужен обработчик `AddHandler application/x-httpd-ea-php83___lsphp .php .phtml`. Настройка в cPanel сама по себе не переключала фактический runtime, явный обработчик проверен в отдельной папке и затем применён к корню. Правила PHP сохраняются при серверной установке.

## Откат и ограничения

Автоматический откат возвращает предыдущий код и корневые файлы, **не откатывает БД**: новые клиентские записи не должны теряться. Перед несовместимыми изменениями схемы необходим отдельный план миграции/совместимости. SQL-копии хранятся вне web root; их восстановление требует отдельной оценки данных после deploy.

Статическое демо публикуется только вручную и отказывается загружаться при наличии серверного index.php. Рабочие обновления приложения публикуются автоматически через release pipeline.
