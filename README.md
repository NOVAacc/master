# Master — платформа онлайн-записи

Рабочее приложение: https://edu.china.kg. Страница регистрации: https://edu.china.kg/register. Серверная версия опубликована 16 октября 2026 через GitHub Actions.

## Рабочий первый этап

Laravel 12 + Inertia 2 + React 19 + TypeScript + Tailwind 4.

- Регистрация мастера, вход и выход; защищённый кабинет.
- Создание и редактирование услуг, цены и длительности, отключение услуг.
- Недельное расписание с выходными и часовым поясом мастера.
- Публичная страница `/m/{slug}` и запись клиента без регистрации.
- Свободные слоты с шагом 30 минут, автоматическое или ручное подтверждение.
- Подтверждение, отмена и завершение записей в кабинете.
- Серверная проверка рабочих часов, блокировок и пересечений. MySQL-транзакция с блокировкой строки мастера сериализует конкурирующие бронирования.
- Ограничение частоты входа/регистрации/записи, CSRF и изоляция данных мастеров.

## Локальный запуск

Нужны PHP 8.2+, Composer 2, Node 22 и SQLite либо MySQL 5.7+.

```sh
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate
npm ci
npm run build
php artisan serve
```

Откройте `/register`. Учётные записи и реальные клиенты не добавляются сидером; паролей по умолчанию нет. Времена записей хранятся в UTC, отображаются в часовом поясе мастера (по умолчанию Asia/Bishkek).

## Проверки

```sh
php artisan test
npm run check
npm run build
```

Единый автоматический процесс проверяет приложение на MySQL 5.7, включая конкурентное бронирование двумя отдельными процессами. Локально на SQLite этот тест пропускается: SQLite не доказывает работу MySQL row locks.

## Публикация

`BOSH — проверка и публикация` — единственный автоматический процесс для изменений в `main`: проверяет код на MySQL 5.7, собирает production-архив без `.env` и dev-зависимостей, проверяет установку и откат и затем публикует эту же сборку. Отдельные проверки для pull request используют MySQL 5.7. Диагностика хостинга и расписания, заполнение примеров, публикация логотипов и резервный установщик запускаются только вручную.

Перед установкой и после успешной проверки сайта автоматически удаляются старые каталоги сборок. Сохраняются активная версия из `current` и предыдущая версия из её записи публикации. `shared`, база данных и резервные копии не очищаются. Очистка использует блокировку установщика и не проходит по символическим ссылкам.

Установщик расшифровывает архив в приватный каталог, делает резервную копию БД, выполняет миграции и переключает release. APP_KEY и storage сохраняются. Публичные страницы и недоступность приватных файлов проверяются после установки; при неудаче возвращается предыдущий код. Точные пути и ограничения отката описаны в `docs/deployment-jaz.md`.

Статический preview теперь публикуется только вручную и отказывается перезаписывать активное серверное приложение.

## Дальнейшие этапы

Полный календарь, перерывы и исключения в расписании через кабинет, карточки и история клиентов, уведомления и восстановление пароля, роли администратора, эксплуатационные резервные копии. Текущая версия — первый запускаемый этап, не весь продукт.
